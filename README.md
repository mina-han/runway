# Runway — 잔고 소진일 대시보드

NH농협 2개 · 우리은행 1개 계좌의 거래내역에서 매달 반복되는 결제일과 금액을 뽑아,
현재 잔액으로 며칠을 버틸 수 있는지(런웨이) 계산하는 단일 파일 대시보드입니다.

> ⚠️ 실제 금융 거래내역이 들어 있습니다. **private 리포지터리로만** 유지하세요.

## 열기

`dashboard.html`을 브라우저로 열면 됩니다. 외부 의존성이 없는 단일 파일이라
서버 없이 더블클릭으로 동작합니다.

## 화면

| 영역 | 내용 |
|---|---|
| 소진일 경고 | 잔고가 0원 아래로 내려가는 날짜와 부족 금액 |
| 현재 잔액 | 계좌별 잔액. 직접 고치면 소진일이 즉시 다시 계산됨 |
| 잔고 흐름 | 결제일마다 계단처럼 떨어지는 잔액 예측 곡선 |
| 일별 출금 예정 | 날짜별 예정 출금과 잔액 |
| 5–7월 실적 분석 | 수입·지출 구성, 금융비용 부담률, 전체 거래내역 |

기준일 · 예측기간(30~180일) · 시나리오 3종을 바꿔가며 볼 수 있습니다.

- **출금만** — 수입을 하나도 넣지 않은 가장 보수적인 계산
- **계약 수입 포함** — 임대료·아동수당처럼 계약으로 정해진 수입만 반영
- **배우자 이체까지** — 배우자 이체를 가장 최근 달 수준으로 가정

## 갱신

새 명세서를 `1. 은행 거래내역 데이터/` 에 넣고:

```bash
python build/analyze.py && python build/build.py
```

`analyze.py` 가 엑셀을 읽어 `data.json` 을 만들고, `build.py` 가 데이터를
`build/template.html` 에 끼워 넣어 `dashboard.html` 을 생성합니다.
필요 패키지: `pandas`, `openpyxl`.

## 계산 규칙

- **계좌 간 이체 제외** — 같은 사람의 계좌끼리 오간 돈은 수입·지출 어느 쪽에도 넣지 않습니다.
- **결제일** = 최근 3개월 결제일(월별 첫 발생일)의 중앙값.
  1일 결제분은 전월 주기가 늦게 빠진 것으로 보고 전월에 배정합니다.
- **예측 금액** = 월 합계의 평균. 단, 최저·최고가 3배 이상 벌어지는 항목은
  가장 최근 달 값을 씁니다(`변동` 표시).
- **반복 판정** — 3개월 중 2개월 이상 나타난 항목만 예측에 넣습니다.

## 알려진 한계

- 잔액이 자동 갱신되지 않습니다. 명세서 마지막 날짜 기준이라 직접 입력해야 정확합니다.
- 3개월 내내 반복된 항목만 예측에 들어갑니다. 국세·수리비 같은 일회성 지출이
  빠져 있어 **실제 소진일은 예측보다 빠를 수 있습니다.**
- 카드처럼 결제일이 흔들리는 항목은 하루 이틀 오차가 납니다.

## 데이터 정합성

거래 168건이 세 계좌 명세서의 합계·기말잔액과 정확히 일치합니다.

우리은행 명세서는 순번 14 · 24 · 95 · 104가 빠진 채 발급됐는데, 거래후잔액이
끊기지 않아 금액(입금 3,416,000원 · 출금 400,000원)을 역산해 `미상(원본 누락)`
으로 넣었습니다. 거래 상대방과 적요는 원본에 없어 알 수 없습니다.
